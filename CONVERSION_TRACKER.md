## Improvement Patterns Applied
- **Camera smooth lerp follow**: Exponential lerp (frame-rate independent) replaces linear move_toward for camera follow. Uses `1.0 - exp(-smoothing * delta)` weight formula.
- **Trauma-based screen shake**: CameraRig.add_trauma(amount) system — trauma decays over time, shake amount = trauma² for organic feel. Triggered on dash (0.15), player damage (0.35), enemy attacks (0.2), enemy death (0.08-0.35 by size), pulse wave (0.25).
- **Input buffering**: Dash input is buffered for 150ms — if pressed during cooldown, fires immediately when ready. Prevents dropped inputs.
- **Smooth HUD bar animation**: HP/XP/Boss bars lerp toward target ratios in _process instead of snapping instantly. Uses same exponential lerp formula.
- **Projectile trail + glow**: Projectiles now have a 6-point fading trail, OmniLight3D for real-time glow, and spawn impact_burst.tscn on hit (expanding + fading sphere).
- **Tween easing curves**: Collectible pickup uses EASE_OUT + TRANS_BACK for pop, EASE_IN + TRANS_CUBIC for shrink + lift. Enemy death adds spin + CUBIC easing.
- **Collectible spin**: Items rotate continuously while idle for visual appeal.

## Enhancement Pack 4 — Low-HP Heartbeat Audio + Dynamic BPM

### Heartbeat Audio SFX (`audio_manager.gd`)
- **Procedural "lub-dub" heartbeat SFX** (`SFX_HEARTBEAT`) — a procedurally synthesized cardiac auscultation sound (S1/S2 pattern) that pairs with the existing visual heartbeat (mesh scale pulse + emission flash) in `player.gd` / `player2_zerp.gd`. Two low-frequency thumps per beat: "lub" (55 Hz fundamental + 110 Hz body harmonic, 0.12s, louder) followed by a 0.15s gap and "dub" (same frequencies, 0.08s, 60% volume). Fast attack + exponential decay envelope gives a percussive chest-felt throb rather than a tonal beep. The universal audio shorthand for critical health in games (Doom, Zelda, Call of Duty).
- **`_gen_heartbeat()`** — new procedural sound generator in the audio manager. Total duration ~0.35s — short enough that rapid heartbeats (at high BPM + low HP) don't overlap into a drone.
- **`play_heartbeat_sfx(intensity)`** — new public API that plays the heartbeat at a scaled volume. Intensity (0..1) maps from -24 dB (whisper, just crossed the HP threshold) to -6 dB (clearly felt, near death). Uses a dedicated `AudioStreamPlayer` rather than the round-robin SFX pool so the heartbeat never steals a combat SFX slot and vice versa. Master volume is applied; SFX volume is intentionally NOT fully applied so the heartbeat remains audible when critical even if the player lowered SFX volume.
- **Cleanup on death/restart** — `_on_player_died()` and `_on_game_restarted()` both stop the heartbeat SFX player so it doesn't carry over after death or into a new run.

### Dynamic Heartbeat BPM (`player.gd` + `player2_zerp.gd`)
- **BPM accelerates as HP drops** — previously the visual heartbeat used a fixed 90 BPM (P1) / 75 BPM (P2). Now the BPM dynamically scales from the baseline at 25% HP to a critical rate at 5% HP: P1 goes 90→140 BPM, P2 goes 75→125 BPM. The heartbeat audibly and visibly accelerates as the player nears death, matching the rising urgency. Linear interpolation between thresholds, clamped.
- **Audio-visual sync** — the heartbeat SFX fires exactly once per beat cycle, synchronized with the visual "lub" pulse (phase 0). Phase wrap-around detection (`_heartbeat_prev_phase > TAU * 0.5 and beat_phase < TAU * 0.5`) triggers the SFX on the beat boundary. Audio intensity scales with HP proximity to zero (0 at threshold, 1 at 0 HP), mirroring the visual emission intensity.
- **P2 parity** — `player2_zerp.gd` receives the same audio + dynamic BPM system with slightly lower BPM values (75→125 vs P1's 90→140) reflecting P2's character profile.

- **Graze detection** — `_physics_process` in `enemy_projectile.gd` now checks if the projectile is within `ENEMY_PROJECTILE_GRAZE_RADIUS` (2.8m) but outside `ENEMY_PROJECTILE_HIT_RADIUS` (1.5m) of the player. This creates a ~1.3m "graze band" where the SFX triggers. Each projectile can only graze once (flagged via `_has_grazed`) so a bolt lingering near the player doesn't replay the SFX. Co-op aware — P2 gets the same graze detection using the shared `_has_grazed` flag so the projectile only grazes once total (either player).
- **New constant** — `ENEMY_PROJECTILE_GRAZE_RADIUS` (2.8) in `game_constants.gd`.

### Boss Intro Card (`boss_intro_card.gd` + `hud.gd`)
- **Dramatic full-screen boss name overlay** — `boss_intro_card.gd` (Control added to HUD) shows the boss's name in large gold text (36pt) centered on a dark semi-transparent panel with a red border, with a subtitle tag ("⚠ BOSS", "☠ MEGA-BOSS" for HP ≥ 500, "🌍 WORLD BOSS" for world bosses). The card slides in from the left with ease-out-back overshoot (0.35s), holds for 1.6s, then slides out to the right with ease-in-cubic (0.35s). A semi-transparent dark backdrop fades in/out with the card for contrast.
- **Cinematic boss appearances** — previously boss spawns had a boss HP bar slide-in + HUD message + SFX_BOSS_SPAWN, but no dramatic "title card" moment. The intro card gives boss appearances a cinematic beat — the player sees the boss's name in large text centered on screen, creating an anticipation moment before the fight begins. The card is purely visual — doesn't block input or pause the game. Coexists with the boss HP bar entrance animation (which slides down from above) and the HUD message.

### Critical Hit Screen-Edge Flash (`crit_flash.gd` + `hud.gd` + `game_manager.gd` + `projectile.gd`)
- **New `critical_hit` signal** — `GameManager.critical_hit(mod_color: Color)` signal emitted by `projectile.gd` when a crit lands. The mod_color parameter lets the flash be tinted to the weapon mod's color for thematic variety.
- **Gold screen-edge glow on crits** — `crit_flash.gd` (Control added to HUD) listens to `critical_hit` and plays a brief gold-colored screen-edge glow. The flash color is a blend of 60% gold + 40% the weapon mod's color, so crits always read as "golden" while fire mods flash orange, ice mods flash cyan, void mods flash purple, etc. The flash has a sharp onset (first 15% of the 0.30s duration, ease-out quadratic) then a gentle fade (remaining 85%, ease-in cubic) — reading as a "lingering glow" rather than a linear drain. Max alpha 0.22 (subtle but visible).
- **Cooldown** — 0.08s cooldown prevents rapid-fire crits from stacking the flash into a persistent glow. The first crit flashes, subsequent crits within the cooldown are suppressed.
- **New visual feedback layer** — previously crits had the gold damage number + hit-stop freeze + SFX_CRIT_HIT, but no screen-level visual effect. The screen-edge flash adds a fourth feedback channel — a peripheral glow that the player registers subconsciously, reinforcing the "that was a good hit" feedback loop without requiring the player to look at the damage number.

## Enhancement Pack 21 — Environmental & Combat Action SFX

### Destructible Crate Shatter SFX (`destructible.gd`)
- **Shatter SFX** — the destructible crate shatter had particles + light flash + camera shake + hit-stop but no audio. The existing `SFX_BREAKABLE` noise hit (0.25s, 0.45 vol) — already used for breakable walls and crystal wraith shards — now also plays when destructible crates shatter. Previously crate destruction was completely silent, creating an inconsistency with breakable walls (which played `SFX_BREAKABLE` on shatter) and a jarring gap between the visual spectacle (25-particle explosion + light flash + camera shake + hit-stop freeze) and the complete absence of audio. The noise-hit timbre reads as a physical crack/break rather than a tonal effect.

### Graviton Pull Activation SFX (`enemy_graviton.gd` + `audio_manager.gd`)
- **New SFX_PULL** — a deep descending gravitational whomp (90→45 Hz, 0.30s, 0.40 vol) that plays when the Graviton activates its gravity pull. The low-frequency sweep conveys a massive force engaging — the sound of space being bent. Added to the `_PITCH_VARIATION_SFX` list for natural micro-detuning.
- **Pull activation wiring** — the Graviton's gravity pull activation had a visual warning ring (appears on the ground 1.5s before pull) + emission brightening but no audio when the pull actually engaged. The player had no audio cue that the pull was active until they were already being dragged toward the Graviton. Now the SFX_PULL whomp fires at the exact moment `pull_active = true`, giving the player an audio cue to start dodging.

### Wildlife Flee Start SFX (`wildlife.gd` + `audio_manager.gd`)
- **New SFX_WILDLIFE_FLEE** — a tiny startled chirp (1400 Hz, 0.05s, 0.10 vol) that plays once when a wildlife creature transitions from wandering to fleeing. The short, high sound reads as a small animal's startled reaction — the audio cue for "it saw you and is running." Intentionally very quiet (0.10 vol) so it doesn't compete with combat sounds.
- **Flee transition wiring** — the flee state had only a visual emission brightening (1.2→2.0 emission_energy_multiplier) but no audio. The player could walk past wildlife without realizing they'd scared it. The SFX fires only on the wander→flee transition (not every frame while fleeing) so a single encounter produces exactly one chirp.

### Player Landing SFX (`player.gd` + `player2_zerp.gd` + `audio_manager.gd`)
- **New SFX_LAND** — a low thud (0.10s noise hit, 0.25 vol) for when Zorp touches down after being airborne (reverse-gravity exit, bounce pad landing, big fall). Added to the `_PITCH_VARIATION_SFX` list for natural micro-detuning.
- **Fall-distance pitch scaling** — the landing SFX pitch scales down with fall distance: a gentle 2m hop plays at 1.2× pitch (light, barely audible), a 10m+ slam plays at 0.7× pitch (deep, solid thump). This mirrors the existing fall-distance scaling on the squash intensity (0.6→1.8), dust size (0.6× intensity), and camera shake (0.12× intensity) — all four feedback channels now scale together. Uses `play_sfx_pitched()` for explicit pitch control.
- **P2 parity** — `player2_zerp.gd` `_play_landing_effect()` also plays `SFX_LAND` (at fixed 1.0× pitch since P2's landing effect doesn't track fall distance), maintaining co-op audio parity.

### Monolith Buff Activation Dedicated SFX (`monolith.gd` + `audio_manager.gd`)
- **New SFX_BUFF_ACTIVATE** — a warm ascending C major arpeggio (C5→E5→G5→C6, 0.06s per note, 0.30 vol) distinct from `SFX_HEAL` (two-note G5→B5 chime). The ascending major triad is the universal audio shorthand for a positive status change in games — conveying "you just got powered up" rather than "you just got healed."
- **Monolith buff activation wiring** — monolith buffs (Speed Surge, Power Surge, Wisdom Aura) previously used the generic `SFX_HEAL` sound. The distinction matters because monolith buffs are offensive/utility buffs (speed multiplier, damage multiplier, XP multiplier), not healing — the audio should match the intent. The 4-note ascending arpeggio is more triumphant than the 2-note heal chime, matching the visual buff-activation effect (upward beam of particles + light flash + screen shake) that already existed.
